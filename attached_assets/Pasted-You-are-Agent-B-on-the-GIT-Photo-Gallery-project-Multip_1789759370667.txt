A user types an occasion ("flowers for valentines day"). You return 2-3
flowers from the gallery that suit it, and save the result to a shared feed.

Two model calls, both text-only (use groq.textModel(), NOT the vision model
— neither call needs to see an image):

1. DEDUP CALL. Ask the model whether any existing feed entry already answers
   this occasion, sending existing entries' "name" and "occasion" values. On
   a match, return that entry with reused: true and write nothing new. The
   point is that two people asking for Valentine's flowers get the same
   bouquet rather than two near-identical entries.

2. PICK CALL. Send the catalog from buildCatalog() (already written for you)
   and require strict JSON back: { name, occasion, flowers, reason, note }.
   - "name" is a short bouquet title like "Valentine's Classic"
   - "occasion" is the normalized occasion — this is what dedup matches on
   - "flowers" is 2-3 filenames
   - "reason" is why these flowers suit the occasion
   - "note" is "" when the picks genuinely fit, otherwise an honest caveat

CRITICAL: validate every returned filename with flowers.isValidFile(). The
model WILL sometimes return a plausible flower that isn't in this gallery,
like "white-lily.jpeg". Drop invalid ones. If fewer than MIN_PICKS (2)
survive, retry the pick once, then return 502 rather than storing a broken
bouquet. Never store an unvalidated filename. This is the single most
important rule in your task.

Also required:

- When the gallery doesn't really cover the request (a funeral, blue
  flowers), still return picks and put the honest caveat in "note". Do not
